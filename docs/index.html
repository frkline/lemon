The 🍋 Workflow

Four labels, one feedback loop.

Lemon’s entire surface in your Linear workspace is four labels and one comment. The popover just shows you what’s happening; the truth lives in Linear, where your team already works.

Under the hood

A menu bar app, a real terminal, and a small local model.

The orchestrator lives in your menu bar.

A SwiftUI menu bar app watches your Linear queue. Two icons: idle and active. It never opens windows you didn’t ask for.

When a 🍋 issue lands, the orchestrator creates a worktree at /tmp/lemon-{id}, launches Claude Code inside it, and pipes the pane output to a log file. You can Join from the popover at any time — the tmux session is real, attaches in iTerm2 or Terminal.app, and stays running if you close the popover.

Why a real terminal? Because the model needs to see what a senior engineer would see. Headless agents lose the texture of "command 14 errored, ANSI red, here’s the stack."
Plate 1. Popover — live, with menu bar grounding HRP-37 picked up, planning.
Fig. 1. The classifier flow 2 min silence → 1 JSON → 1 gated action.

A second model watches the first.

Gemma 4 (E4B or E2B, your choice) runs locally via SwiftLM & MLX on Apple Silicon. After two minutes of pane silence, Lemon hands it the tail of the log and asks: "what’s happening?"

The classifier returns a four-state JSON (running, blocked_prompt, stuck, waiting, complete) plus an optional action. For unambiguous confirmations — a "Trust this MCP server? [y/N]" — it answers. Anything ambiguous, it raises 🍋 Waiting and sits down.

Safety: Gemma's "type something" actions are gated through a hard allowlist: y · n · yes · no · 1–9. Anything outside that list is dropped before it reaches the pane.

Setup

Five steps. Mostly downloads.

Onboarding is a small five-card wizard that walks you through pasting a Linear API key, choosing repos, generating an optional LEMON.md to teach Lemon your conventions, and downloading the local model.

Made for Apple silicon.

A big chunk of Lemon’s value is the silence detector — plus auto-accepting obvious confirmations, plus unsticking dumb prompts that Claude can’t see past on its own. All of that needs a local model running, which is why onboarding gates Continue on a downloaded Gemma and a SwiftLM binary.

Both are pulled inside the wizard. The model is from mlx-community, the runner is a signed release from SharpAI/SwiftLM. Nothing is built from source.

A Self-test button in Settings boots the runner, fires one classify() call, and shows you the actual response. The error tooltip carries the log stream predicate ready to paste into Console.app.

Labels are created for you.

The last onboarding step provisions all four labels in every Linear team you have access to, then verifies your Claude Code login. By the time you press Start Lemon, the workspace is ready to receive its first 🍋.

If your Linear admin already created custom 🍋 labels with the same names, Lemon adopts them (fetch-or-create). Colors are advisory — your existing ones win.

Everything in one pane.

Settings is the single canonical place to check what Lemon is configured against — Linear key, workspace mapping, Gemma model path, SwiftLM binary — and to fire the on-demand Self-test before you trigger a real session.

What it does & doesn’t do

A short list of promises.

Lemon’s job is starting Claude Code sessions, watching them, and getting the result back into Linear — so you can skip the routine parts of your workflow (the obvious confirmations, the wait-for-PR cycle, the context juggle) and keep your attention on the work that needs thinking.

In your house

What stays on your Mac

  • ✓Linear API key — only in macOS Keychain. Never in a file or env var.
  • ✓Workspace paths — UserDefaults. Never sent anywhere.
  • ✓Session logs — written to /tmp/lemon-log-{id}.txt, wiped on cleanup.
  • ✓The local model — ~5 GB in Application Support. Loaded on launch, killed on quit.
  • ✓Source on GitHub. Audit it before you trust it.
Off your machine

What goes out

  • →Linear GraphQL — issues, labels, comments. Standard Linear API surface.
  • →Claude API — via the Claude Code CLI you already authenticated.
  • →HuggingFace — once, to fetch the Gemma quant during setup.
  • →GitHub — once, to fetch the pinned SwiftLM release.
  • ×No telemetry. No analytics. No model traffic. Gemma runs entirely on the GPU.

Honest scope

What Lemon is, and isn’t.

It is

Personal workflow tooling

  • ·A menu-bar orchestrator that decides when to start a Claude Code session and what context to drop into it.
  • ·Glue between your Linear queue and your Claude Code CLI.
  • ·A small local Gemma classifier that watches your terminal pane for "Trust this MCP server?"-style confirmations and answers the obvious ones.
  • ·Built for one developer — the one running it. Not a SaaS, not a team product.
It isn’t

An AI service

  • ×Not a Claude reseller. Lemon never sees, holds, or proxies your Claude API traffic. It launches the claude CLI you already authenticated.
  • ×Not an AI agent product. The intelligence is Claude Code. Lemon’s job is starting it, watching it, and getting the result back into Linear.
  • ×Not multi-tenant. One Mac, one developer, one Linear workspace.
  • ×Not a competitor to Anthropic, Linear, or anything else in your stack. It just sits between them.

The point isn’t "Claude, but in a menu bar."

It’s skipping the dumb routine stuff — the tags you’d kickstart by hand anyway, the trust prompts you’d answer the same way every time, the PR wait you’d just sit through. Lemon orchestrates those out of your day.

And it makes Linear the surface, not a separate dashboard. You’ve been triaging there all morning anyway. Tag the ones you want kickstarted, get back to the work that actually needs your head.

That’s it. That’s the whole pitch.
