Onboarding · Design note

The same room, lit for the first time

Onboarding renders inside the very same MenuBarExtra popover window the user lives in afterward — LemonApp swaps OnboardingView for PopoverView in one closure. So onboarding is not a front door; it is the daily popover before there are any sessions in it. We hold the warm-glass shell, the 340-pt width, the header anatomy, and the rise/stagger entrance fixed, and let only the content change. When the user presses Start Lemon, nothing resizes or recolors — the window stays put and the empty session list slides in where the wizard was.

Decision — same shell, not a front door

The current wizard declares its own .frame(width:520).background(.regularMaterial), so the popover balloons to a 520-pt light-mode panel with serif headlines, then snaps to the 340-pt warm popover the instant setup completes. That resize-and-recolor jolt is the tell that it’s a different app. We design at 340 pt on the thick warm glass. Ethos 07 (“built for the corner — everything assumes a 340-pt popover”) makes this non-negotiable, and matching the width is what makes “same surface” literally true rather than just thematically close. Narrow forces honesty: each step does one job, stacked vertically, instead of a two-column desktop form.

Seven principles, applied to first-run
01
Material over stroke
Steps live on thick glass; fields and the segmented track are thin glass that thicken to regular on focus/selection. No outlines — depth is blur and fill, exactly as in the daily UI.
02
Warm, not cold
We replace .regularMaterial (the cold system panel) with the warm rgba(33,27,17,·) base. The light background goes; the amber dark arrives on step one.
03
Color is earned
One lemon per step — the CTA (or the Draft with Claude action, which is the step’s real primary). The progress rail is neutral, not yellow. Status appears only at dot scale on the Ready legend.
04
Machine truth in mono
API keys, the Gemma checkpoint, the folder path, and the LEMON.md preview are SF Mono. Titles, labels, and helper prose are SF Pro. No serif display face — the type is the system stack.
05
Width-stable identity
Linear/GitHub use the same fixed favicon tiles as the session list. The connected-identity row on step 2 is the exact card the user re-meets in Settings.
06
Quiet by default
No emoji heroes, no big illustration. The loud moment is the single CTA. Even “connected” and “Waiting” are a 6-px dot, not a banner.
07
Built for the corner
340 pt, ≥28-pt hit targets, tall and scrollable. The wizard never presumes a window to breathe in — it breathes in the popover.
The progress indicator

The current top-edge lemon progress bar spends yellow a second time on every screen — a direct violation of “color is earned.” We replace it with a step rail in the header’s right slot, exactly where the live “2 running” count pill sits once configured (so the header anatomy is identical day one and day two). It encodes the sequence honestly — onboarding really is ordered, you must connect before you can map a repo — using the system’s own opacity ramp rather than a new color: done steps are secondary dots, the current step is a primary capsule, upcoming steps are quaternary outlines. We deliberately rejected 01/02/03 numerals: at 340 pt they add machine-noise to a human header, and “1 of 4” already lives in each step’s eyebrow for the reader who wants the count.

Token mapping

Everything above is built from existing tokens: thick/thin/regular glass (Materials), --lemon / --citrus on the one CTA, the --primary→--quaternary text-and-dot ramp, r6 fields/buttons inside r10 blocks inside the r14 popover (concentric corners), 4-pt spacing, the Linear/GitHub favicon SVGs, the settings switch, and the rise .52s cubic-bezier(.2,.75,.2,1) stagger. Between steps, content uses the existing horizontal slide (LD.slide).

New
Patterns onboarding needs that the foundation doesn’t define yet — flag for a top-up:
  • Step rail — header-right progress affordance: 5-px dots on the primary/secondary/quaternary ramp, current step a 14×5 r3 capsule. Reusable anywhere a finite sequence needs a quiet position marker.
  • Segmented control — two-option toggle (Linear/GitHub, 4B/2B). Thin r10 track; selected segment thickens to the regular tier. Today’s system has the .cap pill and buttons but no segmented selector.
  • Editable text field — settings only shows a read-only masked credential. Onboarding needs the live input states: resting thin glass, focus = regular tier + brighter .20 neutral ring + lemondrop caret, mono value, tertiary placeholder, optional inline Verify affordance.
  • Dependency chip — pill with a status-colored leading dot (tmux ✓, hf · sign in). A small extension of the existing .cap.
  • Inline link style — “create one ↗” is rendered secondary, not the platform blue the current wizard uses, to keep the palette closed. Confirm this as the standard link treatment.

Settled — kept the merged step (4 steps, not 5): an earlier draft split Connect (tracker/identity) and Workspace (repo mapping) into two steps because 340 pt rewards one-job-per-step. We kept them merged: the binding — this identity routes this folder — is only legible when you set it in one place, with the identity card sitting directly above the path it routes. Splitting scattered that mapping across two panes, and the pane scrolls now, so the vertical room is free. The remaining open call: whether the Local-AI Download belongs in the body (shown here) with the footer Continue staying neutral until the pull finishes, vs. a single footer action that changes label — both keep one yellow, but the state model differs.
