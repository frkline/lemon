# #86 — Keep Lemon sessions from straying into the user's personal-data folders

A Lemon-spawned session traversed the home dir (a broad `find ~`/`grep -r` from a runaway
subagent), tripping macOS TCC prompts for Downloads, Photos, and Music — attributed to Lemon.
This PR ships the interim soft guard (containers, #15, remain the structural fix).

## What changed
1. **Session-directory guidance in the injected context** (`WorktreeRunner.writeContext`): the
   Session Environment block now tells the session its working area is the session directory
   `/tmp/lemon-{slug}/` (multi-repo aware — cross-repo navigation is fine), explicitly blesses dev
   servers/infra and toolchain home config/caches (`~/.npm`, `~/Library/Caches`, `~/.docker`,
   git/gh/ssh), and discourages reading/recursively scanning the TCC personal-data trees
   (`~/Downloads`, `~/Desktop`, `~/Documents`, `~/Pictures`, `~/Music`, `~/Movies`) plus unrooted
   `find`/`grep`/`rg` from `~` or `/`. Mirrored into `LEMON.md`.
2. **Pinned Lemon's own subprocess cwd to `/tmp`** in `WorktreeRunner.shell()` and `runSync()` so
   no Lemon-spawned helper can inherit `$HOME` — satisfies CLAUDE.md's "all subprocesses must
   `cd /tmp` first" invariant. Commands needing a specific dir already use `git -C`/`cd`.
3. **Locked in the "no usage descriptions" guarantee**: new `InfoPlistPrivacyTests` fails the
   build if any Downloads/Photos/Music/Camera/Contacts/Calendars `NS*UsageDescription` is ever
   added to `Info.plist`; added a documenting comment in `Info.plist`.

## Scope correction during review
Reframed twice per reviewer feedback: boundary is the **session directory** (not the single
worktree) so multi-repo workspaces work, and the guard only discourages the TCC personal-data
trees (not all of `~`) so dev servers, infra, and toolchain home caches keep working.
